# 커밋 전 컨벤션 검토

커밋 전에 현재 브랜치에서 변경된 코드가 코딩 컨벤션을 지키는지, 코드 품질에 문제가 없는지 검토한다.

## 참조 파일

- 검토 기준: [conventions.md](conventions.md)

검토를 시작하기 전에 `conventions.md`를 읽고, 그 안의 규칙만을 기준으로 판단한다.

## 진행 순서

### 1. 변경된 코드 가져오기

아래 명령으로 현재 브랜치의 변경 사항을 모두 모은다.

- `git branch --show-current`: 현재 브랜치 확인
- `git diff main...HEAD`: main에서 갈라진 뒤 이 브랜치에 커밋된 변경 (현재 브랜치가 main이면 생략)
- `git diff HEAD`: 아직 커밋하지 않은 변경 (staged + unstaged)
- `git status --short`: 새로 추가된(untracked) 파일 확인. 새 파일은 내용 전체를 변경된 코드로 보고 읽는다.

변경된 코드가 없으면 "검토할 변경 사항이 없습니다."라고 알리고 끝낸다.
`package-lock.json` 같은 잠금 파일, 빌드 결과물, 바이너리 파일은 검토하지 않는다.

### 2. 규칙별로 판정하기

`conventions.md`의 각 규칙에 대해 변경된 코드를 확인하고 `✅ 통과` 또는 `❌ 개선 필요`로 표시한다.
변경된 줄(추가·수정된 줄)만 판정 대상으로 삼고, 건드리지 않은 기존 코드는 판정하지 않는다.
해당 규칙에 걸리는 코드가 변경 사항에 없으면(예: DB 조작 코드가 없음) `✅ 통과 (해당 없음)`으로 표시한다.

출력 형식:

```
## 검토 결과 (브랜치: <브랜치명>, 변경 파일 N개)

### 네이밍
- ✅ 통과 | 변수명, 함수명: 카멜 케이스
- ❌ 개선 필요 | 상수: UPPER_SNAKE_CASE — src/lib/news.ts:12
...

### 포매팅
...

### 코드 품질
...
```

### 3. '개선 필요' 항목의 수정 방법 안내

`❌ 개선 필요` 항목마다 다음을 알려준다.

- 위치: `파일경로:줄번호`
- 문제: 어떤 규칙을 어떻게 어겼는지 한두 문장
- 수정 예시: 현재 코드와 수정한 코드를 나란히 보여준다

```ts
// 현재
const maxNewsCount = 20;

// 수정
const MAX_NEWS_COUNT = 20;
```

검토만 하고 파일을 직접 수정하지는 않는다. 사용자가 수정을 요청하면 그때 고친다.

### 4. 모두 통과한 경우

모든 항목이 `✅ 통과`이면 결과표 뒤에 다음 문장을 출력한다.

**커밋 준비가 완료되었습니다!**
